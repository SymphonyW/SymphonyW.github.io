常见图片格式全解析：JPG、PNG、GIF、WebP、AVIF、SVG 有什么区别？

平时保存图片时，我们经常会看到 .jpg、.png、.gif、.webp、.svg 这些后缀。它们看起来都能“显示一张图”，但背后的设计目标完全不同：有的适合照片，有的适合截图，有的适合图标，有的适合动画，有的适合印刷或后期处理。

理解图片格式的核心，不是背后缀名，而是看它在几个问题上的取舍：是否压缩、是否有损、是否支持透明、是否支持动画、适合照片还是图形、文件体积和兼容性如何。

一、先搞懂几个关键概念

在具体看格式之前，先把几个常见术语捋清楚。

概念 含义 对选格式的影响
位图 用一个个像素记录图像 照片、截图通常是位图，放大后会模糊
矢量图 用路径、形状、颜色描述图像 图标、Logo、示意图适合矢量，放大不失真
有损压缩 压缩时丢掉一部分细节 体积小，但反复保存会降低画质
无损压缩 压缩后能还原原始像素 适合截图、文字、设计稿，但体积可能更大
透明通道 支持背景透明或半透明 做图标、贴纸、UI 素材时很重要
动画 支持多帧连续播放 表情包、短动图会用到

一句话概括：照片优先考虑有损高压缩，图标和截图优先考虑无损与透明，Logo 和插画优先考虑矢量。

二、常见图片格式逐个看

1. JPG / JPEG：最常见的照片格式

JPG 和 JPEG 本质上是同一种格式，只是扩展名写法不同。它最大的特点是有损压缩，非常适合存储自然照片，比如风景、人像、商品图。

优点：

  • 压缩率高，文件体积通常较小
  • 兼容性极好，几乎所有设备和软件都能打开
  • 很适合色彩连续、细节丰富的照片

缺点：

  • 不支持透明背景
  • 不适合文字、线条、截图，容易出现模糊和噪点
  • 反复编辑并保存会逐渐损失画质

适合场景：博客封面照片、相机导出的普通照片、商品照片、社交平台图片。

不适合场景：Logo、图标、带透明背景的素材、文字截图、需要长期反复编辑的源文件。

2. PNG：清晰、无损、支持透明

PNG 是一种无损压缩位图格式，常用于截图、UI 素材、透明图标和需要保留清晰边缘的图片。

优点：

  • 无损压缩，文字和线条边缘清晰
  • 支持 Alpha 透明通道，可以做半透明效果
  • 适合截图、按钮、图标、设计稿预览

缺点：

  • 对照片的压缩效率不如 JPG、WebP、AVIF
  • 大尺寸照片保存成 PNG 时体积可能非常大

适合场景：软件截图、网页截图、二维码、透明背景图片、UI 元素、需要保持像素级清晰的图。

不适合场景：大量高清摄影图、博客中体积敏感的大图。

3. GIF：老牌动图格式

GIF 最出名的是“动图”。它历史很久，兼容性强，但技术上比较老：颜色最多只有 256 色，所以复杂画面容易失真。

优点：

  • 支持简单动画
  • 兼容性非常好
  • 适合小尺寸、短循环、颜色简单的动图

缺点：

  • 颜色数量有限，不适合高质量照片
  • 文件体积经常比看起来更大
  • 透明效果很弱，只支持简单透明，不支持平滑半透明

适合场景：简单表情包、小图标动画、低色彩短循环动画。

不适合场景：长视频片段、复杂色彩动画、高清动效。很多时候，用 WebP、APNG 或直接用视频格式会更合适。

4. WebP：Web 场景的实用型选手

WebP 是面向网页优化的图片格式，既支持有损压缩，也支持无损压缩，还支持透明和动画。它经常可以在保持相近视觉质量的情况下，比 JPG、PNG、GIF 更小。

优点：

  • 同时支持有损、无损、透明、动画
  • 通常比 JPG/PNG/GIF 更省体积
  • 很适合网站图片优化

缺点：

  • 在一些老旧软件或旧系统中兼容性不如 JPG/PNG
  • 作为长期归档格式不如 JPG、PNG、TIFF 普遍

适合场景：网页配图、博客图片、缩略图、透明 Web 素材、动图替代。

不适合场景：需要给所有传统软件直接打开的图片归档、印刷交付源文件。

5. AVIF：更高压缩率的新一代格式

AVIF 基于 AV1 编码技术，压缩效率很高。它通常能在相同画质下比 JPG 和 WebP 更小，尤其适合需要极致压缩的 Web 图片。

优点：

  • 压缩率很高，适合节省带宽
  • 支持透明、HDR、高色深等现代特性
  • 对复杂照片和渐变画面表现很好

缺点：

  • 编码速度通常比 JPG/WebP 慢
  • 老旧浏览器、图片软件、内容系统的支持可能不完整
  • 调试和批量处理工具生态没有 JPG/PNG 那么成熟

适合场景：追求加载速度的网页图片、移动端流量敏感页面、图片数量很多的网站。

不适合场景：要求最大兼容性的图片分发、编辑链路复杂的素材流转。

6. SVG：图标、Logo、示意图的首选

SVG 不是位图，而是矢量图格式。它本质上是 XML 文本，用路径、形状、颜色来描述图像，所以可以无限放大而不失真。

优点：

  • 放大不失真，适合高清屏
  • 文件体积通常很小，尤其适合简单图形
  • 可以用 CSS 控制颜色、大小和动画
  • 适合 Logo、图标、流程图、架构图

缺点：

  • 不适合复杂照片
  • 复杂 SVG 也可能变得很大、渲染变慢
  • 来自不可信来源的 SVG 需要谨慎处理，避免脚本或外链风险

适合场景：网站 Logo、图标、技术示意图、流程图、架构图、可缩放插画。

不适合场景：照片、复杂纹理图、真实光影图像。

7. HEIF / HEIC：手机照片里常见的高效格式

HEIF 是容器格式，HEIC 是 Apple 设备上常见的 HEIF 文件扩展名。很多手机会默认用它保存照片，因为它比 JPG 更省空间，还能保存更多信息。

优点：

  • 体积通常比 JPG 更小
  • 支持更高色深、多图、景深、Live Photo 等扩展信息
  • 很适合手机本地照片存储

缺点：

  • Web 直接使用不如 JPG/WebP 普遍
  • Windows、旧设备、部分网页系统打开时可能需要转换
  • 分享给他人时经常要转成 JPG

适合场景：手机照片存储、相册备份、Apple 生态内流转。

不适合场景：网页直接展示、跨平台无障碍分享。

8. TIFF：印刷、扫描和归档常用

TIFF 常见于扫描仪、出版、印刷、医学影像和专业图像归档。它可以支持无损压缩、高色深、多页图像和丰富元数据。

优点：

  • 画质保真度高
  • 支持高色深和专业色彩管理
  • 适合扫描、印刷、档案保存

缺点：

  • 文件通常很大
  • 不适合作为网页图片
  • 普通用户日常分享不方便

适合场景：印刷交付、扫描归档、专业修图中间文件、文档影像。

不适合场景：网页加载、社交分享、普通博客配图。

9. BMP：简单但体积大的老格式

BMP 是 Windows 生态里很早期的位图格式，结构简单，但通常压缩能力弱，文件体积大。

优点：

  • 格式简单
  • 在 Windows 环境中兼容性好

缺点：

  • 体积大
  • 不适合网络传输
  • 现代实际使用场景越来越少

适合场景：某些老软件、测试图像处理流程、特殊 Windows 程序兼容。

不适合场景：网页、博客、日常图片分享。

10. RAW：相机保留的“数字底片”

RAW 不是单一格式，而是一类相机原始数据格式，比如 .cr2、.nef、.arw、.dng 等。它保存的是传感器捕获的原始信息，适合后期处理。

优点：

  • 保留最多原始信息
  • 后期调整曝光、白平衡、色彩空间更灵活
  • 适合专业摄影工作流

缺点：

  • 文件很大
  • 不能直接作为网页图片使用
  • 需要 Lightroom、Capture One、Photoshop 等软件处理

适合场景：摄影后期、商业修图、需要最大调整空间的原始素材。

不适合场景：直接上传网页、聊天分享、最终交付图。

四、几个最容易混淆的对比

JPG vs PNG

如果是照片，用 JPG；如果是截图、文字、线条、透明背景，用 PNG。

JPG 会为了压缩丢掉细节，所以照片看起来问题不大，但代码截图、UI 截图、二维码这类边缘清晰的内容会明显变糊。PNG 虽然更清晰，但如果拿它保存大幅照片，文件体积会膨胀得很厉害。

PNG vs SVG

PNG 是像素图，SVG 是矢量图。

同一个 Logo，如果用 PNG，放大后会模糊；如果用 SVG，放多大都清晰。因此网站图标、Logo、架构图、流程图优先 SVG。但如果图像是照片，SVG 就不合适。

GIF vs WebP

GIF 胜在历史悠久和兼容性，WebP 胜在效率和画质。

如果只是做传统表情包，GIF 还能用；如果是网站上的动画素材，WebP 通常体积更小、颜色更好。如果动画较长，最好直接考虑 MP4、WebM 这类视频格式。

WebP vs AVIF

WebP 更像“稳妥的现代格式”，AVIF 更像“压缩率更强的新格式”。

WebP 编解码速度和生态成熟度更均衡，适合大多数网站。AVIF 在体积和画质上很有优势，但编码速度、老旧环境兼容、工具链支持都要额外确认。实际项目里经常会用“AVIF 优先，WebP/JPG 兜底”的方式。

HEIC vs JPG

HEIC 更适合手机内部存储，JPG 更适合跨平台分享。

如果照片只是存在手机相册里，HEIC 可以节省空间；如果要上传网站、发给不同设备的人、放进文档或博客，转成 JPG 或 WebP 往往更省心。

五、实际应该怎么选？

使用场景 推荐格式 原因
博客封面、摄影图 JPG / WebP / AVIF 照片类内容需要控制体积
网页截图、代码截图 PNG / WebP 无损 保持文字和线条清晰
Logo、图标、流程图 SVG 可缩放、清晰、体积小
透明背景贴图 PNG / WebP 支持透明通道
简单动图表情 GIF / WebP GIF 兼容强，WebP 更省体积
长动画或视频片段 MP4 / WebM 比 GIF 更高效
手机照片归档 HEIC / JPG HEIC 省空间，JPG 更通用
扫描件、印刷交付 TIFF / PNG 保真度高
摄影后期源文件 RAW / DNG 保留最大调整空间

如果只记一套日常规则，可以这样选：

  1. 照片用 JPG/WebP，追求极致压缩可考虑 AVIF
  2. 截图、二维码、透明图用 PNG
  3. Logo、图标、示意图用 SVG
  4. 动图尽量用 WebP 或视频，GIF 只做兼容选择
  5. 专业后期保留 RAW/TIFF，发布时再导出成 WebP/JPG

六、常见误区

误区一：PNG 一定比 JPG 清晰

不完全对。PNG 是无损，所以它不会额外破坏像素；但如果原图本来就是低分辨率，存成 PNG 也不会凭空变清晰。

误区二：文件越大画质越好

也不一定。体积大可能只是格式不合适。例如一张照片用 PNG 保存会很大，但视觉效果未必比高质量 JPG 或 WebP 好。

误区三：SVG 一定很安全

SVG 是文本格式，理论上可以包含脚本、外链等内容。自己写的 SVG 问题不大，但用户上传或来源不明的 SVG 不能随便内联到页面里。

误区四：GIF 是做动画的最佳格式

GIF 只是最老、最通用的动图格式，不代表最高效。现在网页动画通常可以优先考虑 WebP、APNG、MP4 或 WebM。

七、总结

图片格式没有绝对的“最好”，只有是否适合当前场景。

JPG 适合照片，PNG 适合清晰截图和透明素材，GIF 适合简单兼容动图，WebP 和 AVIF 适合现代网页优化，SVG 适合图标和示意图，HEIC 适合手机存储，TIFF 和 RAW 更偏专业生产链路，BMP 则更多是历史和兼容场景。

真正的选择逻辑可以浓缩成一句话：

看内容类型选格式：照片看压缩，截图看清晰，图标看矢量，动画看时长，专业素材看后期空间。
