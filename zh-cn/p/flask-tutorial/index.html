Flask 实战教程：面向 Python 开发者的轻量 Web 后端入门

Flask 的魅力在于“小”：它不会一开始就替你规定项目结构、数据库 ORM、表单库、登录系统和管理后台。但这种自由也意味着你需要自己决定边界。本文会从一个可运行的小项目开始，逐步把自由组织成可维护的工程结构。

如果你已经会 Python 函数、装饰器、虚拟环境和基础 HTTP，Flask 很适合作为第一个 Web 后端框架。它既能写返回 HTML 的传统网站，也能写 JSON API；既能单文件快速验证想法，也能用应用工厂、Blueprint 和扩展支撑中型项目。

你已有的 Python 能力 在 Flask 中如何对应
函数 一个视图函数处理一个路由
装饰器 @app.get()、@app.post() 绑定 URL
字典和列表 可以直接返回 JSON 风格数据
模板字符串思维 用 Jinja2 渲染 HTML 页面
模块拆分 用 Blueprint 组织路由
单元测试 用 Flask test client 测接口行为

一、Flask 是什么

Flask 是一个轻量级 WSGI Web 框架。它的核心只处理 Web 框架最基础的几件事：

  • URL 路由；
  • 请求对象和响应对象；
  • Cookie、Session、上下文；
  • Jinja2 模板集成；
  • 静态文件；
  • 错误处理；
  • 扩展机制。

数据库、表单校验、登录认证、后台任务、API 文档等能力通常通过扩展或你的业务代码组合出来。这和 Django 的“全家桶”风格不同：Django 默认给你很多约定，Flask 默认给你一个很薄但很灵活的核心。

一次请求在 Flask 中大致会经过这些阶段：

  1. WSGI Server 接收 HTTP 请求；
  2. Flask 创建请求上下文；
  3. 根据 URL Rule 匹配视图函数；
  4. 执行 before_request 等钩子；
  5. 运行视图函数；
  6. 返回字符串、字典、模板响应、重定向或 Response 对象；
  7. 执行 after_request 等钩子；
  8. WSGI Server 把响应发回客户端。

你可以把 Flask 理解成一个“请求响应协调器”：它不会强迫你怎么写业务，但会把请求到函数、函数到响应这条主线打通。

from flask import Flask, jsonify, request


app = Flask(__name__)

items: dict[int, dict[str, object]] = {}
next_id = 1


@app.get("/health")
def health() -> dict[str, str]:
    return {"status": "ok"}


@app.get("/items")
def list_items():
    q = request.args.get("q", "").strip().lower()
    result = list(items.values())

    if q:
        result = [item for item in result if q in str(item["name"]).lower()]

    return jsonify(result)


@app.post("/items")
def create_item():
    global next_id

    data = request.get_json(silent=True) or {}
    name = str(data.get("name", "")).strip()
    price = data.get("price")

    if not name:
        return {"error": "name is required"}, 400

    try:
        price = float(price)
    except (TypeError, ValueError):
        return {"error": "price must be a number"}, 400

    if price <= 0:
        return {"error": "price must be greater than 0"}, 400

    item = {"id": next_id, "name": name, "price": price}
    items[next_id] = item
    next_id += 1

    return jsonify(item), 201


@app.get("/items/<int:item_id>")
def read_item(item_id: int):
    item = items.get(item_id)

    if item is None:
        return {"error": "item not found"}, 404

    return jsonify(item)

@app.post("/items/form")
def create_item_from_form():

from flask import Flask


def create_app(test_config: dict | None = None) -> Flask:
    app = Flask(__name__, instance_relative_config=True)

    app.config.from_mapping(
        SECRET_KEY="dev",
    )

    if test_config is not None:
        app.config.update(test_config)

    from app.blueprints.items import bp as items_bp

    app.register_blueprint(items_bp)

    @app.get("/health")
    def health() -> dict[str, str]:
        return {"status": "ok"}

    return app

items: dict[int, dict[str, object]] = {}

@bp.get("")
def list_items():

@bp.post("")
def create_item():

    data = request.get_json(silent=True) or {}
    name = str(data.get("name", "")).strip()
    price = float(data.get("price", 0))

    if not name or price <= 0:
        return {"error": "invalid item"}, 400

    item = {"id": next_id, "name": name, "price": price}
    items[next_id] = item
    next_id += 1

    return jsonify(item), 201

八、数据库与扩展怎么选

Flask 不自带 ORM。常见组合是：

需求 常用选择
ORM Flask-SQLAlchemy 或 SQLAlchemy
数据库迁移 Flask-Migrate / Alembic
登录态 Flask-Login
表单和 CSRF Flask-WTF
API 参数校验 Marshmallow、Pydantic 或 Webargs
REST API 快速组织 Flask-RESTful、Flask-Smorest
后台任务 Celery、RQ、Dramatiq

初学时不要一次性把所有扩展装满。建议顺序是：

  1. 先用内存字典理解路由和请求；
  2. 再接 SQLite 和 SQLAlchemy；
  3. 再加数据库迁移；
  4. 页面项目加 Flask-WTF；
  5. 有登录需求再加 Flask-Login；
  6. API 项目再考虑 Marshmallow、Pydantic 或 OpenAPI 相关扩展。

Flask 的扩展生态很丰富，但扩展越多，越需要清晰的初始化位置。应用工厂模式正是为了解决这个问题。

def test_health():
    app = create_app({"TESTING": True})
    client = app.test_client()

    response = client.get("/health")

    assert response.status_code == 200

def test_create_item():
    app = create_app({"TESTING": True})
    client = app.test_client()

    response = client.post(
        "/items",
        json={"name": "Mouse", "price": 99},
    )

    assert response.status_code == 201
    body = response.get_json()
    assert body["name"] == "Mouse"
    assert body["price"] == 99


def test_reject_invalid_item():
    app = create_app({"TESTING": True})
    client = app.test_client()

    response = client.post("/items", json={"name": "", "price": -1})

    assert response.status_code == 400

测试重点不是“把每一行都跑一遍”，而是保护接口行为：状态码、响应结构、错误分支、鉴权和关键业务规则。这样后面把内存字典替换成数据库时，测试能告诉你外部行为有没有变。

常用状态码：

状态码 场景
200 OK 查询成功
201 Created 创建成功
204 No Content 删除成功且无响应体
400 Bad Request 参数语义错误
401 Unauthorized 未登录或凭证无效
403 Forbidden 已登录但无权限
404 Not Found 资源不存在
409 Conflict 资源冲突
500 Internal Server Error 未预期服务端错误

如果你写的是 API，建议从一开始就统一错误格式。否则前端会在不同接口里解析不同形状的错误响应。

十二、Flask 常见坑

坑 更稳的做法
所有代码堆在 app.py 入门可以，项目变大后用应用工厂和 Blueprint
把开发服务器用于生产 生产使用 Gunicorn、Waitress、uWSGI 或托管平台
不设置 SECRET_KEY 从环境变量读取，并在生产环境使用强随机值
手写 HTML 字符串 用 Jinja2 模板，避免未转义内容混入页面
表单写入不做 CSRF 页面项目使用 Flask-WTF 或等价方案
SQL 用字符串拼接 使用 ORM 或参数化 SQL
错误响应格式不统一 API 项目尽早统一错误结构
Blueprint 里塞太多业务 路由负责 HTTP，复杂规则移到 service 层

十三、Flask 与 FastAPI 怎么选

维度 Flask FastAPI
框架风格 轻量、自由、扩展组合 类型驱动、API 契约强
页面渲染 Jinja2 体验成熟 也能做，但主流认知偏 API
请求校验 需要自己选扩展或手写 Pydantic 深度集成
自动文档 需要扩展 内置 OpenAPI 文档
异步支持 不是核心优势 ASGI 原生更适合异步 API
入门感受 概念少，适合理解 Web 本质 工程化 API 体验更完整

如果你想理解 Web 后端的底层主线，或者写一个页面 + 少量 API 的项目，Flask 很舒服。如果你目标是类型契约明确的纯 API 服务，尤其需要自动 OpenAPI 文档，FastAPI 往往更省心。

十四、学习路线

建议按这个顺序继续：

  1. Jinja2 模板继承、宏和过滤器；
  2. Blueprint 和应用工厂；
  3. Flask-SQLAlchemy + Flask-Migrate；
  4. Flask-WTF 和 CSRF；
  5. Flask-Login；
  6. 错误处理和日志；
  7. pytest + test client；
  8. Gunicorn / Waitress / Docker 部署；
  9. Nginx、HTTPS 和线上监控。

Flask 的好处是你可以每次只学一小块。先把请求响应、模板和测试跑通，再慢慢引入数据库、登录、表单和部署能力，学习曲线会平滑很多。
