Linux 广泛用于服务器、开发环境和各种计算设备。日常使用 Linux，最常接触的是终端、文件、权限、进程和网络：通过命令管理文件与软件，运行程序，查看日志，并在出现问题时逐步找到原因。

这篇教程从零基础开始，将常用概念和实际操作结合起来。主线使用 Ubuntu 24.04 LTS、Bash 和一个小型 HTTP 服务，逐步介绍文件操作、权限管理、日志分析、开发环境、进程与网络，再进入服务管理和 Shell 自动化。示例代码均包含在正文中。

不需要先学会 Python，也不需要购买云服务器。 Windows 用户可以用 WSL 2；已有较新的 Ubuntu 环境也可以使用，软件版本和个别输出可能不同。

2. 准备一个真正可用的 Linux 环境

先区分三个概念。 Linux 内核负责进程、内存、设备等底层工作；Ubuntu 这样的发行版把内核、软件包和系统工具组织起来；Bash 是解释你输入的命令的 Shell。终端只是承载输入输出的窗口。打开一个黑色窗口不代表已经进入 Linux。

Windows 主线：在管理员 PowerShell 中先查看可安装的发行版，再安装指定版本：

1
2

wsl --install -d Ubuntu-24.04

以列表中的实际名称为准。按提示重启，再打开 Ubuntu，创建 Linux 用户和密码。密码输入时通常没有星号或其他回显，这是正常现象。该密码与 Windows 登录密码不是同一个概念。

如果已经安装 Ubuntu，直接使用现有环境。检查并进入：

1

wsl -d Ubuntu-24.04

已有环境名称可能只是 Ubuntu，此时最后一条改成 wsl -d Ubuntu。列表中 VERSION 应为 2；确实需要转换旧环境时，才使用 wsl --set-version Ubuntu 2，名称仍按实际替换。安装要求和异常处理见 Microsoft WSL 安装文档。

macOS 用户可准备一台 Ubuntu 虚拟机，Apple Silicon 选择 ARM64 镜像。已有 Linux 电脑或 Ubuntu 虚拟机的读者可以直接继续。macOS 自带终端使用的系统工具与 GNU/Linux 有差异，不能把它当成本教程的 Linux 环境。

3. 文件、路径、编辑器：日常工作的基本盘

Linux 文件名区分大小写，App.py 和 app.py 是两个名字。路径用 /。/ 是文件系统根目录，~ 是当前用户的家目录，. 是当前目录，.. 是上一级；/root 则是 root 用户的家目录。

目录 通常用来做什么 常见内容
/home/用户名 普通用户文件 代码、实验数据、个人配置
/etc 系统配置 SSH、服务和其他软件的配置
/var/log 日志 查系统或应用运行记录
/tmp 临时文件 临时测试；不能依赖其长期保存
/usr/bin 系统安装的可执行程序 查 python3、git 实际来自哪里
/opt 额外部署的软件 本教程的服务文件
/proc 内核提供的进程和系统信息 理解它不是普通磁盘目录即可

4. 用户与权限：解决 Permission denied

执行 id 看 UID、主组和附加组，再观察：

1

ls -l ~/linux-lab/notes/day1.txt

输出可能是：

1

-rw-r--r-- 1 alice alice 17 Sep 14 10:00 day1.txt

第一位表示类型：- 是普通文件，d 是目录，l 是符号链接。后面三组分别给所有者、所属组、其他用户。alice alice 分别是所有者和组名。

权限 对普通文件 对目录
r，值 4 读内容 列出目录中的名字
w，值 2 修改内容 在目录内增删、改名条目，通常还需要 x
x，值 1 允许直接执行 穿过这个目录，访问其中的路径

所以 644 是所有者读写、组和其他人只读；755 是所有者读写执行、其他人读执行；600 是只有所有者读写。数字是每一组内部相加，不是一个需要死记的编号。

1
2
3

chmod 600 ~/linux-lab/notes/day1.txt
ls -l ~/linux-lab/notes/day1.txt
chmod u=rw,go=r ~/linux-lab/notes/day1.txt

目录上的 x 非常关键：即使文件是 644，如果别人不能经过它的父目录，仍然读不到。删除文件主要取决于父目录权限，还会受 sticky bit、ACL 等限制，不能只看文件有没有 w。

sudo 是按配置以其他身份执行一个命令，常见目标是 root。安装系统软件需要它，写自己的代码通常不需要。用 sudo 启动编辑器或构建工具，可能在项目内留下 root 所有的文件。

练习修复一个明确的错误所有者：

1
2
3
4

sudo touch ~/linux-lab/notes/root-owned.txt
ls -l ~/linux-lab/notes/root-owned.txt
sudo chown "$(id -un):$(id -gn)" ~/linux-lab/notes/root-owned.txt
printf 'ownership fixed\n' >> ~/linux-lab/notes/root-owned.txt

$(...) 把命令输出嵌入参数；这里得到当前用户和主组。只改指定文件，不把整个 /usr、/etc 或共享项目递归改成自己所有。

另一类常见坑是 sudo echo 内容 > /etc/某文件：> 由当前 Shell 处理，echo 提权不能让外层 Shell 获得写权限。需要写系统配置时可用 sudoedit 文件，或者明确使用 printf '内容\n' | sudo tee 文件。后者默认覆盖，所以仍要先核对目标。

排错顺序： id 看你是谁 → ls -ld 目标及父目录 看权限 → namei -l 完整路径 看路径的每一级 → 确认文件是否应由你修改。不要直接 chmod -R 777；它会让更多人获得写入和执行权限，也掩盖真正的所有者问题。

动手练习： 不看答案解释 -rwxr-x---；说明“文件可读但无法访问”的一种原因，并修复上面那个 root 所有文件。

5. Shell、管道和日志：把命令组合成工作流

Shell 在程序执行前处理变量、引号、通配符、管道和重定向。很多“命令奇怪地失效”，实际是参数在进入程序前就变了。

1
2
3
4

lab_dir="$HOME/linux-lab"
printf '%s\n' "$lab_dir"
printf '%s\n' '$lab_dir'
ls "$lab_dir/notes"

第一条 printf 输出路径，第二条输出字面量 $lab_dir。赋值时 = 两边没有空格。双引号允许变量展开，同时避免路径中的空格被拆开；单引号保留字面文本。注意 "~/linux-lab" 中的 ~ 不会展开，改用 "$HOME/linux-lab"。规则可查 Bash 引号文档。

输入、输出与错误。 一个普通命令有标准输入 0、标准输出 1 和标准错误 2：

写法 效果
command > out.log 标准输出写入文件，覆盖旧内容
command >> out.log 标准输出追加到文件
command 2> err.log 标准错误单独写入文件
command > all.log 2>&1 先重定向标准输出，再让标准错误跟随它
a | b 把 a 的标准输出交给 b 的标准输入
a | tee out.log 输出既显示在屏幕上，也写入文件

> all.log 2>&1 与 2>&1 > all.log 不同，重定向从左到右处理。普通 | 不自动传递标准错误。不要对同一个输入文件直接写 grep ... file > file，Shell 会先清空文件。详见 Bash 重定向文档。

准备一份能得到确定答案的日志。 下方 cat <<'EOF' 是 here-document：将两行标记之间的内容写入文件。结束的 EOF 独占一行；带引号的开始标记会避免内容中的变量被展开。

先逐步观察，不要直接背一条很长的管道：

1
2
3
4
5

cd ~/linux-lab
wc -l logs/access.log
grep -n 'status=500' logs/access.log
grep -c 'status=500' logs/access.log
awk '$6 == "status=500" {print $5}' logs/access.log
awk '$6 == "status=500" {print $5}' logs/access.log | sort | uniq -c | sort -nr

结果应是总共 6 行、3 次 500，最后一条得到：

1
2

      2 path=/api/orders
      1 path=/api/users

awk 默认按空白分字段，$5 是第五列，$6 是第六列。sort 先让相同接口相邻；uniq -c 只对相邻相同行计数；最后的 sort -nr 按数字倒序排列。这套写法依赖这里约定的日志格式，不适合直接套在任意 JSON 或带空格的字段上。

再做两个高频操作：

1
2
3

grep -n -C 1 'path=/api/users' logs/access.log
sed -n '2,4p' logs/access.log
sed 's/level=INFO/level=DEMO/g' logs/access.log > logs/access.demo.log

grep -C 1 显示匹配行的上下文；sed -n '2,4p' 查看第 2～4 行；替换操作写入新文件，便于比较。对于真实服务，关注时间、请求 ID、错误类型和上下文，不要只数 ERROR 一词。

退出码决定自动化是否可靠。

1
2
3

grep -q 'status=503' logs/access.log
echo $?
mkdir -p notes/check && printf 'directory ready\n'

$? 是上一条命令的退出码，必须紧接着读取。通常 0 表示成功，非零表示其他情况；grep 的 1 是没有匹配，2 是错误，不能把它们混为一谈。a && b 在 a 成功时执行 b，a || b 在 a 失败时执行 b。

默认情况下，管道的退出码取最后一个命令；脚本中的 set -o pipefail 能让前段失败更容易暴露，但不等于整段逻辑从此没有漏洞。详见 Bash 管道文档。

6. 开发环境：让程序在正确的地方运行

在新机器上接到项目，第一步是读项目的 README 和版本约束，再确认系统与工具。不要因为某个程序缺失，就在不同安装教程之间随机复制命令。

1
2
3
4
5
6

进程是运行中的程序，有 PID、用户、状态、工作目录和环境。一个程序可以创建多个进程，一个进程也可以有多个线程。

先用无副作用的 sleep 练习后台任务：

& 把命令放到后台，$! 是最近一次后台任务的 PID，jobs 只列当前 Shell 管理的作业。ps 查看系统进程。正常停止优先使用程序提供的退出方式或 TERM；kill -9 对应 KILL，进程无法捕获它做清理，只在确认对象且正常方式无效时使用。

8. 网络与 SSH：从本机服务到远程机器

先记住地址的含义：127.0.0.1 是当前网络环境自身的 IPv4 回环地址；0.0.0.0 作为监听地址表示所有 IPv4 接口，不是浏览器访问时应填写的服务器地址。端口区分同一台机器上的不同服务。WSL、容器和宿主机有各自的网络边界，不要假设两边的 localhost 总是相同。

先做一个可以立即排错的网络实验。 在终端 A 运行：

#!/usr/bin/env python3
"""A small HTTP service for practicing Linux operations; no dependencies."""

import json
import os
from datetime import datetime, timezone
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from urllib.parse import urlsplit


class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        path = urlsplit(self.path).path
        if path == "/health":
            status, payload = 200, {"status": "ok", "service": "linux-lab"}
        elif path == "/":
            status, payload = 200, {"message": os.getenv("APP_MESSAGE", "Hello Linux")}
        else:
            status, payload = 404, {"error": "not found"}

        body = (json.dumps(payload, ensure_ascii=False) + "\n").encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_request(self, code="-", size="-"):
        # repr escapes control characters in the request target.
        now = datetime.now(timezone.utc).strftime("%Y-%m-%d %H:%M:%S")
        print(
            f"{now} level=INFO method={self.command} "
            f"path={self.path!r} status={code}",
            flush=True,
        )


if __name__ == "__main__":
    host = os.getenv("APP_HOST", "127.0.0.1")
    port = int(os.getenv("APP_PORT", "8000"))
    with ThreadingHTTPServer((host, port), Handler) as server:
        print(f"Listening on http://{host}:{server.server_port}", flush=True)
        try:
            server.serve_forever()
        except KeyboardInterrupt:
            print("Stopping linux-lab", flush=True)

EnvironmentFile 不是随意执行的 Shell 脚本，不能把 export、命令替换或一般脚本逻辑直接写进去。ExecStart 也不会自动按 Bash 解释 >、| 和 ~。After=network.target 描述启动顺序，不保证此时互联网或数据库已经可用。参考 systemd 服务文档源码 与 执行环境文档源码。

#!/usr/bin/env bash
set -euo pipefail

if [[ $# -ne 2 ]]; then
    printf 'Usage: bash %s SOURCE_DIR BACKUP_DIR\n' "$0" >&2
    exit 64
fi

if [[ ! -d "$1" ]]; then
    printf 'Source directory does not exist: %s\n' "$1" >&2
    exit 1
fi

# realpath resolves symlinks; -m also accepts a destination not yet created.
source_dir=$(realpath -e -- "$1")
backup_dir=$(realpath -m -- "$2")
if [[ "$source_dir" == / || "$backup_dir" == "$source_dir" ||
      "$backup_dir" == "$source_dir/"* ]]; then
    printf 'Backup directory must be outside the source directory.\n' >&2
    exit 1
fi

mkdir -p -- "$backup_dir"
# mktemp creates a unique file, even for concurrent runs in the same second.
archive=$(mktemp "$backup_dir/backup-$(date -u +%Y%m%dT%H%M%SZ)-XXXXXX.tar.gz")
# A failed tar command must not leave an incomplete archive behind.
trap 'rm -f -- "$archive"' EXIT
tar -czf "$archive" -C "$source_dir" .
trap - EXIT

printf 'Backup created: %s\n' "$archive"

不要急着运行，先读懂关键行：

写法 用处
#!/usr/bin/env bash 直接执行脚本时，指定用 Bash 解释
$#、$1、$2 参数数量、第一和第二个参数
[[ ... ]]、if Bash 条件判断，例如目录存在与参数数量
>&2、exit 1 报错到标准错误，并返回非零状态
set -u 引用未定义变量时暴露错误
set -e、pipefail 让很多执行失败尽早终止；仍要理解条件和管道例外
realpath 解析真实路径，包括符号链接，避免把备份写回源目录内
mktemp 创建唯一文件，连续运行不会撞名覆盖
trap ... EXIT 失败退出时移除这次创建的不完整归档

脚本限定备份的是普通目录，不允许 /，也不允许备份目录位于源目录内部。否则可能把正在生成的备份再次打包。它适用于自己控制的练习目录，不负责解决多人并发修改目录等复杂情况。

11. 常见故障的排查与恢复

端口占用、权限不足、配置值错误和路径拼写错误，都是运行服务时常见的问题。下面通过前面的示例服务复现这四种情况，观察它们的表现和处理方式。一次只复现一种，恢复并验证健康后，再继续。 这些操作只用于自己的练习环境。

故障 A：端口被另一个程序占用。 先停掉练习服务，在终端 A 启动临时服务器：

1
2

sudo systemctl stop linux-lab
python3 -m http.server 8000 --bind 127.0.0.1 --directory "$HOME/linux-lab/data"

保持 A 运行，在 B 执行 sudo systemctl start linux-lab。尝试访问 /health，它可能返回 404；这是因为当前端口上运行的是静态服务器。现在只看“8000 端口开着”就会误判。

任务：找出真正占用端口的进程，解释为什么 systemd 服务启动失败；恢复正确服务，验证 /health 的 JSON 内容。

故障 B：程序存在，但服务用户无法读取。 在 A 已停止、练习服务恢复正常后，执行：

1
2

sudo chmod 000 /opt/linux-lab/app.py
sudo systemctl restart linux-lab

任务：从日志和权限信息定位原因。不能通过改为 root 运行服务、给全目录 777，或者重装 Python 来修复。

故障 C：环境变量值无效。 修复 B 后，执行 sudo nano /etc/linux-lab.env，把 APP_PORT=8000 改成 APP_PORT=oops，保存并 sudo systemctl restart linux-lab。

任务：确认 Python 报错发生在读取端口配置时；解释为什么在当前终端 export APP_PORT=8000 无法修复这个服务。修复服务实际读取的文件并重新验证。

故障 D：服务的解释器路径拼错。 修复 C 后，执行 sudo nano /etc/systemd/system/linux-lab.service，只把 ExecStart 中的 .venv/bin/python 改成 .venv/bin/python-missing，其他内容不变，再执行：
